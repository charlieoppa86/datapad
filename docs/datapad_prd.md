# PRD: Datapad

## 1. 개요 (Overview)

**제품명**: Datapad

**한 줄 정의**: 동일한 의미의 데이터를 담은 Raw CSV와 AI-ready CSV에 같은 질문을 각각 던져, LLM 답변이 데이터 품질에 따라 어떻게 달라지는지 나란히 보여주는 웹 서비스.

**핵심 컨셉**: "같은 질문 → 다른 답변"을 직접 눈으로 보여주는 것이 제품의 전부다. 복잡한 비교 로직이나 진단 엔진을 만들지 않고, 동일한 질문-응답 패턴을 두 데이터셋에 각각 재사용하는 가장 단순한 구조를 지향한다.

**레퍼런스**: [dartpad.dev](https://dartpad.dev) — 좌측 입력(코드) / 우측 출력(콘솔) / 상단 Run 버튼 구조를 데이터 진단 도메인에 이식.

## 2. 문제 정의 (Problem)

- "AI-ready 데이터가 왜 중요한가"는 개념으로만 설명되고, 실제로 같은 질문에 데이터 품질에 따라 답이 얼마나 달라지는지 체감할 방법이 없다.
- 기존 데이터 프로파일링 툴은 단일 데이터셋의 통계만 보여줄 뿐, "같은 질문에 대한 결과 차이"를 직접 대조해주지 않는다.

## 3. 목표 (Goal)

- 사용자가 Raw CSV와 AI-ready CSV를 업로드하고 질문 하나를 던지면, 두 데이터 각각에 대한 LLM 답변을 나란히 보여줘서 품질 차이를 스스로 체감하게 한다.
- MVP를 통해 "같은 질문에도 답이 다르게 나온다는 것을 사람들이 명확히 인지하는가"라는 핵심 가설을 빠르게 검증한다.
- 아키텍처는 최대한 단순하게: 비교 로직이나 진단 엔진을 별도로 만들지 않고, "데이터+질문 → 답변"이라는 단일 패턴을 두 번 재사용한다.

## 4. 타겟 사용자 (Target Users)

범용 진단 툴로, 두 페르소나를 모두 지원한다.

| 페르소나 | 특징 | 질문 예시 |
|---|---|---|
| 개발자/데이터 엔지니어 | 스키마, 전처리 로직에 관심 | "이 데이터에서 결측치가 있는 컬럼은?", "타입이 일관된 컬럼은?" |
| 비개발자 (마케터/기획자) | 코드는 모르지만 데이터 품질을 이해하고 싶음 | "이 데이터로 고객 나이대를 분석할 수 있어?" |

## 5. 핵심 사용자 플로우 (Core User Flow)

```
[좌측 패널: Raw CSV 업로드]          [우측 패널: AI-ready CSV 업로드]
        ↓ (드래그앤드롭)                      ↓
 [프리뷰 표시]                        [프리뷰 표시]
                        ↓
            [하단: 질문 1개 입력창]
                        ↓
                  [Run 버튼 클릭]
                        ↓
        ┌───────────────┴───────────────┐
   [Raw CSV로 질문 실행]          [AI-ready CSV로 질문 실행]
   (독립적인 LLM 호출 1)          (독립적인 LLM 호출 2)
        ↓                               ↓
   [좌측 결과: 답변 텍스트]        [우측 결과: 답변 텍스트]
```

*(자기 파일이 없으면 화면 상단/구석의 "샘플 CSV 다운로드" 버튼으로 Raw/AI-ready 파일을 받아 바로 업로드 가능)*

1. (선택) 자기 파일이 없는 사용자는 **샘플 CSV 다운로드 버튼**을 눌러 Raw/AI-ready 샘플 파일을 받아 바로 테스트 가능
2. 사용자가 좌/우 패널에 Raw CSV, AI-ready CSV를 각각 업로드 (자기 파일 또는 방금 받은 샘플 파일)
3. 업로드 완료 시 각 패널에 데이터 프리뷰(상위 행 테이블) 표시
4. 하단 질문 입력창에 질문 1개 입력 (양쪽 데이터에 동일하게 적용됨)
5. Run 클릭 → **동일한 질문으로 독립적인 LLM 호출 2번** 실행 (Raw용 1번, AI-ready용 1번)
6. 좌/우 결과 패널에 각 답변을 나란히 출력 → 사용자가 두 답변을 직접 대조하며 차이를 체감

## 6. MVP 기능 범위 (Scope)

### In Scope (MVP에 포함)
- CSV 2개 업로드 (드래그앤드롭 + 클릭 업로드), 파일 크기 제한 **4MB 이하**
- 업로드 완료 시 데이터 프리뷰 표시 (상위 행 테이블, 컬럼명/타입)
- 질문 입력창 1개 (양쪽 데이터에 공통 적용, placeholder로 예시 질문 노출)
- Run 버튼 → **동일 질문에 대한 독립적인 LLM 호출 2회** (Raw / AI-ready 각각)
- 좌/우 결과 패널에 각 답변을 나란히 텍스트로 출력
- 화면 구석에 **누적 방문자 수, 누적 실행(Run) 수** 노출 (작은 텍스트, 사회적 증거 용도)
- **샘플 CSV 다운로드 버튼** (Raw용 1개, AI-ready용 1개) — 클릭 시 미리 준비된 샘플 파일이 다운로드되어, 사용자가 자기 파일 없이도 바로 업로드해 테스트 가능

### Out of Scope (MVP에서 제외)
- 두 답변을 종합해 비교/진단하는 별도 로직이나 요약 (사용자가 직접 눈으로 비교)
- 회원가입/로그인, 이력 저장, 파일 공유
- 3개 이상 CSV 비교, 다중 질문 동시 처리
- 리포트 내보내기, 질문 템플릿

## 7. 기술 설계 (Technical Design)

### 7.1 파일 업로드 & 검증
- 클라이언트 1차 검증 + 서버 재검증으로 4MB 초과 차단
- **4MB는 Vercel 서버리스 함수의 요청 body 제한(4.5MB)보다 작으므로, 별도의 Storage 직접 업로드 없이 파일을 서버리스 함수로 바로 전송해 처리 가능** — 업로드 아키텍처가 단순해짐 (Supabase Storage/서명 URL 같은 우회 로직 불필요)
- CSV 파싱 실패(인코딩/구분자 오류) 시 명확한 에러 메시지

### 7.2 데이터 프리뷰
- 업로드 즉시 상위 10~20행 테이블 렌더링, 컬럼명/타입/행렬 수 표시
- 프리뷰는 일부 행만 처리, 전체 파일은 서버에 임시 보관

### 7.3 LLM 질문-응답 파이프라인 (단순화된 핵심 구조)

- Run 클릭 시, **동일한 질문 텍스트로 2개의 독립적인 LLM 호출**을 각각 실행 (Raw CSV용, AI-ready CSV용)
- 두 호출은 서로의 존재를 모르는 완전히 분리된 요청 — 비교 로직, 메타 프롬프트, 두 데이터를 동시에 넣는 컨텍스트가 전혀 필요 없음
- 각 호출의 입력 구성 (CSV 원본 전체 대신):
  - 컬럼별 메타 요약(타입, 결측치 비율, 고유값 수, 기초 통계)
  - 상위 30행 고정 샘플 (30행 이하면 전량)
  - 사용자가 입력한 질문 원문
- 시스템 프롬프트는 단일 역할만 수행: "아래 데이터 요약과 샘플을 참고해 질문에 답하라" — 비교나 진단을 지시하지 않음
- 진단 방식: 순수 질문 반응형(자유형). 고정 체크항목(결측치/타입 등) 강제 보고 없음
- 결과: 두 호출의 응답을 각각 그대로 좌/우 패널에 렌더링

이 구조의 장점: 백엔드는 "CSV 요약 만들기"와 "질문+요약으로 LLM 호출하기"라는 두 가지 함수만 있으면 되고, 이 함수를 두 데이터에 각각 호출하면 끝난다. 비교 알고리즘, 진단 규칙, 근거 매칭 로직이 전혀 필요 없다.

### 7.4 결과 화면 출력 형식 (확정)
- 좌/우 각각 **자연어 문단만** 출력 (마크다운 구조화, 표, 근거 패널 없음)
- 두 답변을 나란히 배치하는 것 자체가 "비교 리포트" 역할을 대신함 → 별도의 비교 요약을 만들지 않음

### 7.5 아키텍처 (최소 구성)
- 프론트: Next.js (2-pane 업로드 + 프리뷰 + 질문 입력 + Run + 2-pane 결과)
- 백엔드: (1) CSV 요약 생성 함수, (2) LLM API 호출 함수 — 이 두 함수를 각 CSV에 대해 순차 또는 병렬로 2번 호출하는 것이 전부
- 파일 업로드: 4MB 제한이 Vercel 함수 body 한도(4.5MB) 이내이므로, 클라이언트가 CSV를 서버리스 함수로 바로 전송 (Supabase Storage 직접 업로드/서명 URL 같은 별도 경로 불필요 — 구조 단순 유지)
- 상태 저장 없음: 파일은 세션 동안만 메모리/임시저장, 회원 시스템·DB 불필요

### 7.6 누적 카운터 (방문자 수 / 실행 수)
- 회원 시스템이 없으므로 **개인별 집계가 아닌 전체 누적 숫자 1개씩**만 관리 (방문자 수, 실행 수 각 1개)
- 저장 방식: 별도 DB 없이 단순 카운터 저장소(예: KV store 또는 파일/싱글 레코드 DB)로 최소 구현
- 방문자 수: 페이지 로드 시 +1 (중복 방지 로직 없이 단순 카운트 — 새로고침해도 증가하는 수준으로 충분, 정교한 UV 집계는 MVP 범위 아님)
- 실행 수: Run 버튼 클릭(LLM 호출 성공 시) +1
- UI 노출: 화면 우측 하단 또는 상단 구석에 작은 텍스트로 "누적 방문 N · 누적 실행 M" 형태로 표시

## 8. 비기능 요구사항 (Non-functional Requirements)

| 항목 | 기준 |
|---|---|
| 파일 크기 제한 | 4MB / 파일 |
| 응답 시간 목표 | Run 클릭 후 양쪽 답변 모두 출력까지 30초 이내 |
| 에러 처리 | 파싱 실패, 크기 초과, LLM 응답 실패(한쪽만 실패해도 나머지는 표시) |
| 개인정보 | 업로드된 CSV는 세션 종료 후 즉시 삭제, 서버 로그에 원본 데이터 미기록 |
| 브라우저 지원 | 최신 Chrome/Safari/Edge 기준 |

## 9. 성공 지표 (Success Metrics — MVP 검증용)

- 방문자 대비 "CSV 2개 업로드 + Run 클릭 완료" 전환율
- Run 결과 수신 후 재질문(같은 세션 내 추가 질문) 비율
- (정성) 사용자가 두 답변의 차이를 스스로 알아채는지 여부 — 사용자 인터뷰/피드백으로 확인

## 10. 오픈 이슈 / 추후 결정 필요

- LLM API 벤더 선정 (비용/속도/컨텍스트 한도 비교 필요)
- 프리뷰에서 보여줄 행/컬럼 개수 기본값
- 질문 입력창 placeholder에 넣을 구체적인 예시 질문 문구
- 두 LLM 호출을 병렬로 보낼지 순차로 보낼지 (응답 시간 vs 구현 단순성 트레이드오프)
